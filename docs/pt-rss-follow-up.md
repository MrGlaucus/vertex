# PT 刷流后续交付

在第一轮规则分流和容量检查上，增加辅种安全流程、持久化恢复、删种保护与预览、刷流中心、备份恢复及本地镜像构建入口。

## 入口

- 菜单「刷流中心」：总览、任务处理、收益统计、操作记录、删种预览。通过「刷新数据」更新快照，页面显示刷新时间。
- RSS：辅种策略、来源下载器、是否遵守选择规则及免费/HR 检查、等待时长、规则排序方式。
- RSS「自定义正则替换」：可对整个 RSS XML 文本按顺序执行多条正则；原下载链接替换继续保留为兼容范围。
- 下载器：空间保护、严格/宽松空间计算模式、状态有效期、总种子数量上限。上限为 0 时不限制。
- 系统备份恢复：上传后先校验暂存，使用本项目启动脚本，下次启动才切换。

## RSS 全文正则替换

在 RSS 任务编辑页，勾选已有的「自定义正则替换」，把范围设置为「整个 RSS XML 文本」，添加一条或多条规则。没有新增另一套替换开关。

规则格式沿用 `/pattern/flags`：`g` 替换全部匹配，`i` 忽略大小写，`m` 多行匹配，`s` 允许点号匹配换行，支持 JavaScript 捕获组替换（如 `$1`）。规则从上往下依次执行，可上移、下移和删除；替换内容留空表示删除匹配文本。

例如匹配 `/old\.example\.com/g`，替换为 `new.example.com`，会替换 XML 中所有命中的域名，包括标题、简介、详情链接、下载链接和属性。表达式也可匹配整个 XML 片段。替换后必须保持合法 XML，普通文本及属性中的 `&` 需要写成 `&amp;`；CDATA 中按原始文本处理。

处理顺序为：读取原始 RSS（或原始缓存）→ 执行任务的全文替换 → XML 解析及站点适配 → 拒绝/选择规则、辅种和添加。推送种子文件与下载链接两种方式都生效。缓存只保存原文，同一个 RSS 链接被多个任务使用时，各自的替换独立，不会污染缓存。已经入队的重试和辅种候选使用当时解析后的数据，不重复执行全文替换。

原始 RSS 缓存按完整链接共享：普通站点默认 40 秒，lemon/hhanclub 150 秒，sharkpt 及 XML 查看器格式 310 秒。同一服务进程中，相同链接的并发获取会合并为一次站点请求，缓存过期后的同轮任务也只请求一次；请求失败后移除合并状态，后续可正常重试。不同链接分别处理。两个每分钟执行的任务若同轮触发、链接完全相同，会共享一次原始请求；若执行时间错开超过缓存有效期，则会分别获取新内容。

「试运行」使用同一套全文替换，查看替换后解析出的种子；表达式无效或替换后 XML 无法解析时会报错，不添加种子。新建任务默认使用全文范围，但替换开关仍默认关闭。旧任务缺少范围字段时保持「仅下载链接」，只有手动切换为全文后才改变含义；这个兼容范围仍仅在推送下载链接时生效，不改动 XML。

## 刷流中心怎么用

默认进入「总览」：先看下载器是否正常、有哪些重试耗尽或辅种校验失败，再查看名额和空间。四个指标来自当前加载的列表，并不是历史总数；添加与失败重试可能对应同一种子，不能把两个指标相加。

「任务处理」分成三类，默认展示待处理项，支持搜索种子、RSS、下载器及错误，并切换“需要人工关注”或“全部（含已完成 / 已停止）”：

| 列表 | 它记录什么 | 通常如何处理 |
| --- | --- | --- |
| 添加失败重试 | RSS 添加失败后的重试计划、次数和结果 | 等待自动尝试；耗尽后查看错误及日志，修正原因 |
| 添加与辅种确认 | 实际添加请求的登记状态，以及辅种校验和标签确认 | 结果未知时核实；校验失败时检查文件后重新校验 |
| 等待已有数据 | 仅辅种未命中时保留的候选 | 等待原种完成，或移出不需要的候选 |

点击种子名称或“查看详情 / 处理”，可查看当前说明、处理建议并执行对应操作。核实重试、重新校验和停止操作有明确确认说明。停止不会撤回请求；移出候选不删除种子或文件。添加流程完成不代表普通种子已下载完成。本页面不替代下载器的实时种子列表。

「收益统计」按选择规则、站点与下载器、RSS 历史三个视角分别展示，每张表说明统计来源和范围。当前种子的累计流量与本地历史记录不同；种子总大小不是实际磁盘占用，共享文件会重复计入。

「操作记录」是最近 200 条事件日志，可按失败与拒绝、自动重试、辅种过程、删种/暂停/限速筛选。同一个种子可能有多条日志；任务当前状态以任务处理列表为准。添加与重试列表各最多展示最近 500 项，页面说明这个范围，不作为全量任务统计。

「删种预览」选择下载器后主动生成，显示命中规则、拟执行操作和文件保护原因；没有生成预览与“没有规则命中”使用不同的提示。切换下载器会清空旧结果，预览不会执行删除或暂停。

## 辅种

辅种仅使用来源下载器中已有完整数据的 qBittorrent，添加到原种所在机器并使用原种实际保存路径。普通下载与辅种可配置不同的下载器组。

| 策略 | 匹配条件 | 添加行为 |
| --- | --- | --- |
| 安全 | 实际文件相对路径及大小集合完全相同 | 暂停添加、强制校验，通过后才启动 |
| 快速 | 实际文件相对路径及大小集合完全相同 | 暂停添加并跳过校验，确认标签后才启动 |
| 兼容 | 名称相同、种子文件实际总大小相同 | 暂停添加、强制校验，通过后才启动 |

新建任务默认安全模式。快速模式依赖源文件健康状态，文件清单匹配不能代替内容校验。任务设置为暂停时，辅种也保持暂停。

新种先确认 `Reseed`，再处理原种的 `Brseed`。标签失败退避恢复，不重新添加；原种消失时停止补 `Brseed`，保留新种的 `Reseed`。

安全/兼容模式校验不完整时保持暂停，不自动补下载；超过六小时仍未完成校验也进入人工检查状态，可选择「重新校验」。重新校验先暂停目标种子。

「仅辅种」未匹配时不会转普通下载；可等待原种下载完成后重新匹配。等待时长 0 关闭，最大 1440 分钟，每个 RSS 最多 500 项。移出队列不屏蔽仍在 RSS 中的条目。

启用「辅种遵守规则」后，来源还须满足首条命中规则的下载器限制，并重新检查任务的免费/HR 条件。没有启用时沿用旧辅种资格判断。拒绝规则始终先执行。

## 持久化恢复

RSS 的最长休眠保护以当前实例上次成功获取 RSS 的时间为基准。正常重启或重新启用任务后，没有旧运行时间的首次成功获取不会因时间差被拒绝。获取或解析报错不会被当成空列表成功，也不刷新成功时间；合法的空 RSS 则正常记录成功。若首次成功前已经连续获取失败，按首次失败的开始时间判断是否超时。运行中距上次成功获取超过阈值时，恢复的这一轮新候选仍执行休眠保护，之后的新候选正常处理。成功时间在获取完成时更新，不受后续添加失败、通知报错或单小时数量上限影响。手动条目推送和独立重试不会刷新 RSS 获取的健康时间，也不应用这一休眠拦截。

新增 SQLite `brush_state` 表保存容量预占、添加状态、原种/辅种关系、等待项和事件，不改变已有历史表结构。预占、新任务、关系记录在同一事务中创建。每台下载器串行发送添加请求，辅种与删种共享数据操作锁。同一 RSS 定时执行不重叠。

恢复任务每分钟运行，单轮最多五项，实时查询原下载器：

1. 已存在：交给实际容量统计，辅种继续校验和标签确认。
2. 未找到：经过核实窗口后释放预占；添加失败的 RSS 进入独立持久化队列，满足当前规则后在原下载器重试，不依赖条目再次出现在 RSS 中。
3. 离线或查询失败：保留状态，退避等待，不转发其他机器。
4. 校验或标签阶段目标消失：停止恢复，不重新下载。

RSS 首次添加失败后，每 30 秒重试一次，最多重试 5 次（包括首次添加共 6 次），仍失败就放弃。种子文件下载失败也进入队列。队列扫描每 5 秒运行一次，实际启动时间可能有数秒调度延迟或受正在执行的请求影响。任务、次数及日志保存在 SQLite，重启后继续处理。

下载器首次登录后立即读取种子列表，登录和状态轮询分别合并并发请求，防止旧请求的失败覆盖新请求的成功状态。RSS 分流及最终添加前，发现状态未就绪或容量状态过期时先刷新，再判断；暂时无法获取状态的 RSS 条目也保留在重试队列中。提示区分下载器未启用、状态尚未就绪、状态读取失败；读取失败展示隐藏 URL 后的最近错误，不等同于下载器服务停止。

重试前实时查询原下载器；种子已存在时记录成功，不重复添加。下载器离线或查询失败时等待，不消耗添加重试次数。RSS 停用期间不执行。重试仍检查当前规则、免费/HR、推送上限和容量；不再符合时停止，辅种失败不会转成普通下载。刷流中心「RSS 自动重试」显示次数、下次时间及错误，可手动停止；「执行记录」展示安排、开始、成功、失败后再安排、耗尽及停止过程。日志中的错误会隐藏 URL。

非 RSS 添加维持最多五次的原限制；标签或校验恢复持续失败达到 24 次停止自动处理。页面提供「核实 / 重试」「重新校验」「停止恢复」。停止不会撤回已发出的 HTTP 请求，也不会直接释放未知请求预占。

事件保留约 30 天，并定期收敛到最近 10000 条；重复未命中和拒绝按 15 分钟合并。任务与关系不按事件期限清理，以保留去重及保护信息。

## 下载器空间计算

在「下载器 → 编辑 → 空间保护」启用后，可选择空间计算模式。旧配置没有此字段时默认严格模式；空间保护开关默认仍关闭。

| 模式 | 可用空间计算 | 添加新种子的条件 |
| --- | --- | --- |
| 严格 | 当前磁盘剩余空间 − 现有种子未完成大小 − 待确认添加的预占大小 | 再扣除新种子大小后，仍不少于最小剩余空间 |
| 宽松 | 下载器报告的当前磁盘剩余空间，已反映实际文件占用 | 当前剩余空间高于最小剩余空间，不扣除新种子的未来占用 |

宽松模式不累加种子已下载大小来估算磁盘占用，避免辅种共享文件重复统计。慢速、排队、暂停种子的未完成部分和待确认添加请求都不扣减空间；新种子未来可能占用的空间也不提前扣减。状态有效期、剩余空间有效性、下载数量、总种子数量和重复添加检查仍然生效。宽松模式允许未知大小的新种子，不保证所有任务后续同时完成时磁盘空间足够，也不新增自动暂停下载行为。

RSS 使用「当前剩余空间」排序时，启用空间保护的下载器按各自模式计算值从大到小分配；未启用时保持按当前磁盘剩余空间排序。刷流中心显示模式及对应可用空间。切回严格模式后，已有未完成任务和待确认请求会重新计入，无需重建任务。

## 删种保护与监控

预览使用当前删种规则、拒绝规则、顺序、每轮数量及最近状态，显示暂停、限速、仅删种或删种及文件，以及保护原因。预览不执行删除；已有自定义 JavaScript 规则应保持无副作用。

实际自动删种在重新汇报后的等待结束时刷新状态并再次判断规则。添加、校验或标签未结束，关联另一种子仍存在，无法实时核实关联状态，或同一下载器发现名称/大小/保存位置相同及内容路径重叠时保留文件。项目内手动删种入口也接入保护。删除尚未从轮询列表消失时，删除标记阻止新辅种复用数据。

规则收益关联新增任务的命中规则，上传、下载与容量来自仍存在的种子；历史 RSS 汇总使用原历史表。旧任务未迁移规则归属，显示默认/旧任务。站点/下载器收益使用当前种子累计流量；容量为逻辑总量，共享数据会重复计入，不代表实际磁盘占用。

## 备份恢复

SQLite 在线备份生成一致性快照，包含已提交 WAL 数据，不直接复制正在写入的数据库文件。可选择包含种子缓存。

恢复检查必要文件、SQLite 完整性，拒绝路径越界、链接、特殊文件、重复条目，限制大小和数量。默认上传上限 512 MiB、解压上限 8 GiB、条目上限 100000；上传上限可用 `VERTEX_BACKUP_UPLOAD_MAX_BYTES` 调整。

检查通过后暂存到运行目录 `.restore-staging-*`，写入 `.pending-restore.json` 和文件摘要。下次启动前复核摘要，通过恢复日志逐目录切换；失败或发现未完成日志时回滚。原数据保留在 `.restore-previous-*`，不自动清理。

Docker 启动脚本已接入。非 Docker 部署应在应用打开数据库前运行 `node tools/apply-restore.js /实际运行数据目录`；该目录直接包含 `db`、`data`、`config`，须与备份读取的目录一致。

## 兼容性与边界

- 旧 RSS 无新字段时保留旧规则排序和辅种资格判断，策略显示「兼容」。旧单下载器覆盖继续支持，历史仍参与去重，不需要重建 RSS。
- 旧辅种有安全调整：兼容模式先暂停并校验，不再直接跳过校验。
- 预计空间保护默认关闭，总种子上限默认不限制。
- 只增加数据库表，不自动导入其他 fork 私有格式，也不修改下载器已有历史标签。
- 当前支持单个 VERTEX 进程；跨下载器共享磁盘没有统一预算，不做跨机辅种路径映射及共享文件识别。
- 外部直接操作下载器不受本项目锁控制。磁盘预算依赖下载器报告；预分配文件可能造成保守扣减。
- RSS 试运行只展示规则与普通容量，不执行辅种匹配、免费/HR 抓取或历史去重。
- 自适应权重调度和低收益自动删种评分尚未加入，收益页面用于人工判断。

升级前保留原运行数据备份，先用独立下载器验证，再替换正式实例。回退时停止新进程后启动旧进程，不让两个实例同时使用同一数据目录。

## 构建与验证

### 可复用下载器组

在「基础组件 → 下载器组」集中维护命名的下载器集合。RSS 任务普通下载器、RSS 任务辅种下载器、RSS 规则目标下载器均支持引用多个组。配置仅保存组 ID，运行时读取最新成员；改名、增减成员立即对全部引用生效，无需重启或逐个编辑任务。

组与单独选择的下载器取并集并去重。若希望完全通过组维护，应清空对应位置原来单独勾选的下载器。RSS 规则目标依然与 RSS 任务普通下载器范围取交集，因此建议两处均引用相应的组；规则引用空组且没有直接选择成员时不回退到任务里的其他机器。组引用丢失时停止该范围的分配，不能绕过限制。辅种仅使用已启用、状态正常的 qBittorrent；开启「辅种应用选择规则」时同样遵守规则的目标范围。

管理页显示组成员、未启用/已删除状态及所有引用位置（包括未启用任务）。被引用的组不能删除；属于组的下载器需先从组中移除才能删除。修改组成员不迁移或删除已有种子；已发出的请求继续确认结果，尚未发出的请求会重新检查成员范围。失败重试仍保留原下载器核实逻辑，不会因改组而盲目重复添加到另一台机器。

组配置保存于运行数据目录 `data/downloader-groups.json`，随现有备份的 data 目录保存、恢复。旧的直接多选配置及单下载器规则保持兼容。

### RSS 定时运行

RSS 任务编辑页的「定时运行」提供两个可独立启用、也可同时使用的设置，旧任务默认不启用：

- **每日运行时段**：例如 `23:00 → 08:00` 表示每天 23:00 至次日 08:00，包含开始时刻、不包含结束时刻。开始和结束时间不能相同，全天运行应关闭此设置。时段内仍按原 RSS Cron 执行，不在进入时段时额外抓取。
- **到期自动关闭**：选择服务端本地日期和时间，到达截止时刻后取消「启用」并写回 RSS 配置。截止时间优先于每日运行时段；截止后重新启用需修改或关闭此设置。

所有时间按服务端时区解释（容器 `TZ=Asia/Shanghai` 为北京时间），与浏览器时区无关。列表显示运行状态、下一次运行时段和截止时间，每 15 秒刷新，也可手动刷新。截止检查独立于 RSS Cron，每秒检查，并在抓取和真正发送添加请求前再次检查；服务停止期间无法执行，重启时先处理已过期任务。

时段外暂停抓取、新增种子、添加重试和等待辅种处理，不消耗重试次数。辅种候选仍按原等待期限过期，恢复时重新检查规则和容量；计划内暂停不会触发「最长休眠时间」拒绝。到期关闭取消尚未执行的重试和等待辅种并记录日志。已发送请求继续确认结果，已添加种子和已启动的辅种校验、补标流程继续完成。试运行仍仅检查规则与容量，不受定时限制，也不会执行添加或辅种。
